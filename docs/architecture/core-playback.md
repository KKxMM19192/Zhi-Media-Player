# 核心播放架构

Silent Nocturne 的核心播放链路分为共享领域层、Electron 主进程边界、preload API 和 renderer 协调层。该拆分让树操作、队列状态机与播放规则可以脱离 Vue 和 Electron 测试，同时限制 renderer 对本地文件和桌面能力的访问。

## 音乐树与对象边界

分类歌单、当前播放队列、已保存队列和队列历史都以 `MusicTreeNode` 表示内容：

- `TrackNode` 保存独立节点 ID、文件名和本地索引路径；
- `PlaylistNode` 保存独立节点 ID、名称和有序子节点；
- 数组顺序同时表示界面顺序和播放展开顺序。

路径标识本地音乐资源，节点 ID 标识该资源在某个持久化对象中的一次出现。队列允许同一路径出现多次，因此当前播放对象始终按节点 ID 定位，而不按路径猜测。

四类对象具有不同所有权：

- 分类歌单是用户组织的本地音乐索引；
- 当前播放队列是实时编辑和播放的工作对象；
- 已保存队列是与当前队列独立的命名快照，可以单独编辑；
- 队列历史是只读恢复快照，由整体替换、清空、历史恢复和退出乱序等高影响操作自动维护。

跨对象复制会为每个节点生成新 ID，不保留来源关联。移动同一棵树中的节点则保留 ID，因此移动当前音乐或其祖先不会重载媒体；删除当前音乐或其祖先会立即停止并清空播放状态。

共享领域逻辑位于 `src/shared/domain/`，不依赖 Vue、DOM 或 Electron：

- `music-tree.ts`：遍历、查询、复制、选择、删除、插入、移动和内容比较；
- `playback.ts`：分类歌单直属播放、队列递归展开、模式循环和相邻曲目计算；
- `queue-state.ts`：已保存队列、历史快照、历史去重与乱序进入/退出；
- `music-path.ts`：跨树路径比较和索引路径替换；
- `app-state.ts`：可持久化状态的版本化结构和资源预算。

## 队列历史与乱序状态

队列历史默认最多保留 10 条。连续快照内容相同时不重复写入；内容比较忽略节点 ID 和历史元数据，但保留对节点类型、名称、路径、结构、顺序的比较。恢复历史不会消费被恢复条目，恢复出的当前队列会获得全新节点 ID。

四种播放模式按“顺序播放、顺序循环、单曲循环、乱序播放”循环。自然播放结束与用户主动切换曲目使用不同推进原因，因此单曲循环只拦截自然结束，手动上一首和下一首仍可移动。

进入乱序时只洗牌一次，并同时维护：

- 当前显示和执行的扁平曲目工作队列；
- 进入乱序前完整树形队列的独立快照；
- 工作队列曲目 ID 到恢复树曲目 ID 的显式映射。

乱序期间的添加、删除、移动和排序只修改扁平工作队列，不会重新洗牌，也不会修改恢复快照。退出乱序时，退出前的工作队列先写入历史，然后无条件恢复原树。若当前曲目来自进入乱序前的队列，则只重映射节点 ID，不递增媒体版本，音频继续播放；若当前曲目是乱序期间新增且没有恢复映射，则停止播放。进入乱序时展开节点 ID 也会映射到恢复树，因此退出或重启后仍能恢复树的展开状态。

## 进程责任

### 主进程

`src/main/` 负责所有需要本地系统权限的行为：

- 打开系统文件和文件夹选择器；
- 扫描 MP3、FLAC，保留目录层级并裁剪空分支；
- 规范化和比较 Windows 路径；
- 批量检查文件是否存在；
- 读取音频元数据和内嵌封面；
- 选择并授权单文件替换，计算目录根迁移和文件夹精确匹配结果；
- 校验并保存版本化应用状态；
- 为已授权媒体签发短期访问令牌并处理流式读取。

文件夹扫描和修复扫描不会跟随符号链接，并受深度和节点预算限制。索引修复只返回新的索引路径；应用不会移动、重命名、修改或删除音乐文件。应用内删除也只更新索引树和状态。

### Preload

`src/preload/index.ts` 只通过 `contextBridge` 暴露 `SilentNocturneApi` 中列出的固定业务方法。renderer 无法获得 `fs`、`ipcRenderer`、任意 IPC channel 或通用 Electron API。

系统资源管理器拖入使用 `webUtils.getPathForFile(File)` 在 preload 中提取本次拖入文件的真实路径，再调用受控导入 IPC。该能力只接受用户本次拖入的 `File` 对象，不向 renderer 提供查询任意本地路径的接口。

主进程的 IPC handler 会再次验证数量、类型、绝对路径、授权状态和状态 schema，不把 renderer 请求视为可信输入。

### Renderer

Pinia store 位于 `src/renderer/src/stores/app-store.ts`，负责协调：

- 页面、选择、展开、拖拽状态和错误提示；
- 当前队列、已保存队列、历史和乱序事务；
- 调用共享领域函数完成树编辑和路径替换；
- 调用窄 preload API 完成导入、可用性检查、索引修复、状态保存和媒体请求；
- 管理当前节点、播放上下文、进度、音量、模式和暂停状态。

store 会在可能增加节点的修改前同时检查单棵树和整份持久化状态的节点预算。涉及“记录旧队列再替换”的操作会先构造候选历史与候选队列，预算校验通过后才一次性应用，避免出现历史已写入但队列未替换等半事务状态。

主要界面按职责拆分：

- `LibraryWorkspace.vue`：分类歌单导入、编辑和索引维护；
- `QueueWorkspace.vue`：当前队列、已保存队列和历史页面；
- `QueueDrawer.vue`：常驻右侧当前队列；
- `MusicTree.vue`：可编辑或只读树展示，以及树内、跨树和外部拖放事件；
- `PlayerBar.vue`：真实 `<audio>`、媒体装载、进度、传输控制、模式和音量。

拖拽核心变换仍由共享领域函数和 store 完成。renderer 的拖拽适配层只负责区分外部文件、同树移动、跨树复制和保存队列复制，并把目标转换成树插入位置。

## 受控媒体访问

renderer 播放音乐前，需要先通过主进程检查该路径是否属于本次会话已授权的索引。主进程随后签发高熵、有限时长的媒体令牌，renderer 只能获得如下形式的 URL：

```text
sn-media://audio/<token>
```

URL 不包含本地绝对路径。私有协议 handler 将令牌解析回主进程维护的授权路径，并支持标准单段 `Range` 请求，以便 Chromium 音频元素进行媒体探测和进度跳转。未知、过期或格式错误的令牌不会映射到磁盘文件。

内嵌封面由主进程解析，只接受 JPEG、PNG 或 WebP，并限制为最多 5 MiB。没有可用封面时 renderer 使用统一默认图形。

状态加载、文件选择、外部拖入和索引修复成功后，主进程只授权经过验证且实际属于应用状态或用户刚完成操作的音乐路径。保存状态时也会检查所有持久化树中的路径均已授权。

## 状态持久化

当前写入的状态 schema 版本为 `2`，包含：

- 分类歌单树和当前播放队列；
- 已保存队列与队列历史；
- 乱序前树形快照和曲目 ID 映射；
- 当前音乐节点和播放上下文；
- 播放进度、音量、模式和暂停状态；
- 展开的树节点。

主进程仍可读取 schema v1，并迁移原有分类歌单、队列、播放位置和展开状态；新增的保存队列、历史和乱序状态使用安全默认值。schema v1 没有可恢复的乱序快照，其 `shuffle` 推进行为与顺序循环相同，因此迁移时映射为 `repeat-all`。后续写入统一使用 schema v2。

持久化校验覆盖树深度、单树节点数、整份状态总节点数、全局 ID 唯一性、绝对路径、保存队列数量、历史上限、乱序映射完整性、播放引用和数值范围。目前限制为单树最多 50,000 个节点、整份状态最多 500,000 个节点、最多 100 个已保存队列和 10 条历史。

状态文件位于不依赖开发命令或包名推导的稳定应用数据目录；启动时可以从早期默认目录迁移一次有效状态。写入使用目标文件同目录的独占临时文件，刷新文件内容后再原子重命名；并发保存按接收顺序串行执行。

如果状态文件缺失，应用使用默认空状态。如果内容损坏或版本不受支持，应用保留原文件、显示警告并使用空状态启动，不会用空状态立即覆盖原内容。

关闭窗口时，主进程先通知 renderer 刷新最后状态，收到完成确认后才真正关闭窗口。重新启动会恢复队列、当前音乐、进度、音量、播放模式和乱序双状态，但无条件保持暂停，避免自动发出声音。`durationSeconds`、封面、媒体 URL、不可用路径集合和 `mediaRevision` 属于运行时派生状态，不写入状态文件。

## 验证

Vitest 覆盖纯领域树操作、历史与乱序状态机、Windows 路径、临时目录扫描、路径修复、schema 迁移、持久化、store 原子事务、树拖放分流和媒体恢复。文件系统测试只使用受控临时目录，不读取真实音乐库或应用配置。

常规验证命令：

```bash
pnpm lint
pnpm test
pnpm typecheck
pnpm build
```

真实音频输出、Windows 文件选择器、系统资源管理器外部拖入、嵌套拖拽、右键菜单、关闭重启和窗口行为仍需在 Electron GUI 中人工验证。生产构建成功不能替代这些人工检查。
