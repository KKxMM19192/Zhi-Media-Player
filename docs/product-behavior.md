# 产品行为基线

本文件记录 Silent Nocturne 已实现且需要长期维护的用户可观察行为。交互语义、对象关系或数据安全规则发生变化时，应同步更新本文件；进程边界、领域模型、持久化和媒体访问等实现细节见[核心播放架构](architecture/core-playback.md)。

## 核心对象

Silent Nocturne 使用四类用途明确的对象组织和播放本地音乐：

- **分类歌单**：用于长期组织本地音乐索引的树形结构；
- **当前播放队列**：当前实际参与播放、可以实时编辑的树形工作对象；
- **已保存队列**：由当前队列或历史另存的命名快照，保存后可以独立编辑；
- **队列历史**：应用在高影响队列操作前自动记录的只读恢复快照。

音乐文件路径标识磁盘资源，节点 ID 标识该资源在某个对象中的一次出现。同一路径可以在队列中出现多次，每次出现都是可以独立选择、移动和播放的节点。

从分类歌单复制到当前队列、已保存队列或历史恢复结果时，节点会获得新的独立身份。复制后的对象不与来源同步；同一棵树内的移动则保留节点身份。

## 界面与编辑模型

应用主要界面由以下区域组成：

- 顶栏左侧提供设置与索引维护入口；
- 顶栏中部在“分类歌单”和“播放队列”页面之间切换；
- 顶栏右侧控制当前播放队列抽屉；
- 主内容区展示分类歌单，或当前队列、已保存队列和队列历史；
- 当前播放队列可以从右侧滑出，并与主内容区同时使用；
- 底部播放栏始终保留。

分类歌单、当前队列和已保存队列始终可以直接选择和编辑，不区分固定态与单独的编辑态。队列历史只读，但可以恢复或另存为已保存队列。

### 选择与激活

- 单击项目行或复选框会切换该项目的选择状态；
- 双击歌单会选中并展开该歌单；
- 双击音乐会选中并播放该音乐；
- 选中歌单时，其全部后代一并视为选中；
- 取消选择某个后代时，其已选祖先也会退出完整选中状态；
- 复选框区分未选中、全部选中和部分选中；
- 删除、移动和复制多选内容时，只处理最上层的已选祖先，避免重复操作其后代。

右键已选项目会保留现有多选集合，需要处理选择集合的菜单操作会作用于该集合；右键未选项目会先清除原选择，只选中当前项目，再打开菜单。

### 拖放

在已选项目上开始拖动时，拖放对象为当前全部选中内容：

- 同一棵树内拖放执行移动，保留节点身份；
- 不同树之间拖放执行复制，生成独立节点身份；
- 可以插入节点之间，也可以放入歌单内部；
- 已保存队列可以作为同名歌单拖入当前队列；
- 系统资源管理器中的音乐文件和文件夹可以拖入分类歌单、当前队列、已保存队列或队列抽屉的指定位置。

## 音乐导入

应用识别 MP3 和 FLAC 文件，支持通过系统选择器或外部拖放导入单个、多个文件和文件夹。

导入文件夹时：

1. 根文件夹转换为同名歌单；
2. 子文件夹转换为同名子歌单；
3. 保留原始目录嵌套关系；
4. 只保留自身或后代中含有受支持音乐的目录；
5. 完全没有受支持音乐的分支被裁剪；
6. 音乐不会被拍平成单层列表。

同一音乐路径可以出现在不同分类歌单中。在分类歌单的同一直属层级重复导入相同路径时，重复项会被跳过并给出提示；当前队列和已保存队列允许重复路径。

## 分类歌单与当前播放队列

分类歌单用于组织索引。在分类歌单中播放某个歌单时，只播放该歌单直属的音乐，不递归进入子歌单。

当前播放队列可以包含音乐、歌单和嵌套歌单。播放器按照界面顺序从上到下递归展开整棵队列，得到实际播放序列。普通播放期间添加、删除、移动、排序或调整层级后，后续播放顺序以最新队列结构为准。

从分类歌单加入当前队列时，会完整复制名称、树结构、音乐索引和顺序；后续编辑任一对象都不会影响另一方。

### 正在播放项目的编辑行为

删除当前音乐或包含它的祖先歌单时，应用会立即停止播放，并清空当前音乐、进度和播放状态。

移动当前音乐或包含它的祖先歌单时，节点身份保持不变，音乐继续播放且不会重新装载；当前播放对象跟随节点的新位置。

## 已保存队列与队列历史

保存当前队列时，应用完整复制其名称、节点、索引、嵌套结构和顺序。保存结果是可以独立编辑的命名对象。

使用已保存队列播放时：

1. 当前队列在替换前写入历史；
2. 已保存队列被复制为新的当前队列；
3. 复制出的节点具有独立身份；
4. 从新队列的第一首音乐开始播放。

打开已保存队列进行查看或编辑不会改变当前队列。将已保存队列拖入当前队列时，它会保留名称并作为同名歌单插入指定位置，内部结构保持不变。

应用在以下操作前记录当前队列：

- 使用已保存队列完整替换当前队列；
- 从队列历史恢复状态；
- 清空当前队列；
- 退出乱序模式。

普通的单项添加、删除、移动和排序不会单独产生历史。

队列历史遵循以下规则：

- 最多保留最近 10 条；
- 超出上限时淘汰最旧记录；
- 连续内容相同的队列不重复记录；
- 恢复历史不会消费被恢复的记录；
- 恢复结果使用新的独立节点身份；
- 历史本身只读，但可以另存为已保存队列。

## 播放模式与乱序

底部播放栏通过同一模式按钮依次切换：

1. 顺序播放：播放到末尾后停止；
2. 顺序循环：播放到末尾后回到第一首；
3. 单曲循环：音乐自然结束时重复当前音乐；
4. 乱序播放。

单曲循环只影响自然播放结束。用户主动选择上一首或下一首时仍会切换音乐。每次切换模式时，界面会显示图标和短暂文字提示。

### 进入乱序

切换进入乱序模式时，应用只洗牌一次：

1. 保存进入乱序前的完整树形队列；
2. 将队列中的音乐递归展开为扁平列表；
3. 洗牌后将该列表作为乱序期间显示和执行的当前队列；
4. 保存乱序节点与原树节点之间的身份映射。

乱序期间可以继续添加、删除、移动和排序，后续操作不会重新洗牌，也不会修改进入乱序前保存的原树。

### 退出乱序

退出乱序时：

1. 退出前的完整扁平队列写入历史；
2. 乱序工作队列被放弃；
3. 无条件恢复进入乱序前保存的原始树形队列；
4. 切换到用户选择的新播放模式。

乱序期间的修改不会合并回原树。如果当前音乐能映射回恢复后的原队列，音乐继续播放并重新定位节点；如果它只存在于乱序期间新增的队列中，应用会停止播放并清空当前音乐状态。

## 本地文件与异常索引

应用只维护本地音乐的索引和自身状态。应用内的删除、替换和修复操作不会删除、移动、重命名或修改磁盘上的音乐文件和文件夹。

当音乐索引对应的文件不可用时：

- 界面明显标记对应节点；
- 应用不会静默猜测新的文件位置；
- 播放该音乐时不会自动跳过，而是停止并提示文件不可用；
- 用户可以删除索引、选择其他音乐或手动修复。

索引维护支持：

- 为单个音乐节点选择新的文件；
- 将旧目录根映射到新目录根，并保留后续相对路径；
- 根据原文件名从指定文件夹匹配失效音乐；
- 对嵌套歌单进行文件夹匹配时保留原有目录关系；
- 在用户确认后，将完全相同的旧路径替换到分类歌单、当前队列、已保存队列和队列历史中的所有对应节点。

## 播放栏与状态恢复

底部播放栏提供：

- 播放进度和时间；
- 当前音乐封面与文件名；
- 上一首、播放或暂停、下一首；
- 播放模式切换；
- 音量控制。

音乐名称以文件名为准。封面优先使用音频文件内嵌的 JPEG、PNG 或 WebP 图片；没有可用封面时显示统一默认图形。

应用持久化分类歌单、当前队列、已保存队列、队列历史、乱序双状态、当前音乐、播放上下文、进度、音量、模式和树节点展开状态。

重新启动后，应用恢复上次音乐和播放进度，但始终保持暂停，不会自动发出声音。封面、时长、媒体 URL、文件可用性和媒体装载版本属于运行时状态，会在需要时重新获取。
